## 子项 A：玻璃透光 + 高光描边

### 勘查结论（卡内要求先勘查再动手）

**不是层级问题，是配方问题。** A1 停线**不触发**——无需改照片层级，不影响任何几何契约。

| 分级 | 结论 |
|---|---|
| ① | 药丸用 `.background(.ultraThinMaterial, in: Circle()/Capsule())`，材质**本就位于照片层之上**：`ZStack` 顺序为 背景色 → `mainPhoto` → `interfaceOverlay`。层级没有问题。 |
| ① | chrome 祖先链上唯一的 `.opacity()` 在 `V=显示` 时**恒为 1.0**。离屏合成组只在 opacity < 1 时产生（`allowsGroupOpacity` 语义），故稳定显示态下它**不**抑制材质的背景采样。祖先链上无其他滤镜。 |
| ① | `zoomContentView.backgroundColor = .clear`，照片视图尺寸为 `fittedSize`（等比适配框）。**非屏幕比例的普通照片留黑边时，顶/底 chrome 带根本不落在照片矩形内**，身后是 `S2ViewportBackground.color`（`systemBackground`）——没有照片可透。这解释了「随手看总觉得不透」，属几何事实而非缺陷。 |
| ③ | 「全屏铺满」场景下仍显不透，最可能是配方：单用 `.ultraThinMaterial` 在深色环境下偏暗、去饱和，读起来像实心块。**本机无真机/模拟器，无法实测**，故标③。 |

### 实装

新增 `S2ChromeGlass` 配方常量与统一的 `s2ChromeGlassBackground(in:)`，顶部三件 + 底部三件 + 中央指示容器（子项 B）共用同一族：

- 材质之上补**白色薄底 6%**（画布「底色白 ~6%」）；
- **内描边**顶缘白 **55%** 线性渐弱至底缘 **12%**，线宽 1；
- **外圈**白 **22%** 细环，线宽 0.5。

blur 与饱和/提亮沿用系统材质自带的（卡内明示「系统材质能达到同观感即可，不强求逐参数复刻」）。**刻意未叠加 `.saturation()` / `.brightness()`**：这两个滤镜会把子树推进离屏合成，反而打掉材质的背景采样，与本卡目标相反。

截图显示态 chrome 背后为黑、透光弱是预期；**描边不依赖背景**，故那种情形下描边仍在（卡内明示要求）。

| 验收点 | 测试函数 |
|---|---|
| 配方落在画布取值、顶缘亮于底缘、白底足够薄 | `testIC112AGlassRecipeMatchesCanvas` |

## 子项 B：中央状态指示

位置 = **主图几何中心**（视口中心 X + `oneXDisplayCenterY`，故截图的适配带锚定同样正确）。跑道圆框容器复用 A 的玻璃底与描边；内为方形倒角块。**旧右上角小垃圾桶角标已移除**（`primaryMarkOverlay` 整个删除；`s2.mark.primary.accessibility` 转由中央指示的已标记态引用，故目录无孤儿 key）。

**状态解析下沉为纯函数** `S2CenterIndicatorResolver.state`：

1. `V=隐藏` 一律不显示（指示随 chrome 同显隐）；
2. 只有一种态就显示那种；
3. 两态并存显示**最近一次动作**对应的那种（④）；
4. 并存但**无最近动作**（刚翻页到新的一张）取 `marked`——**卡内未覆盖的边角，卡内取定并登记**：待删意图更需要被看见。

四态：已标记＝单块垃圾桶方块；已收藏＝♡ + 收藏到「名」+ 分隔线 + 撤回钮；下滑撤回＝整块淡出（消失即撤回成功的确认，故解析结果为 `nil`，不是独立态）；翻页即随新页状态刷新且**不带动画**（`disablesAnimations` 事务）。

出现/消失 **200 ms** 淡入淡出 + scale **0.9→1 / 1→0.9**，走 `transition` + `withAnimation` 的属性动画，由渲染层推进。
